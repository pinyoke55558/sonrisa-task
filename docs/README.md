## Local development environment

`development/docker-compose.yml` starts everything the application depends on. The backend (Spring Boot, port 8080) and the frontend (Vite, port 5173) run outside Docker.

| Service | Image | Port | What it is | Used for |
|---|---|---|---|---|
| `app-db` | PostgreSQL 18.7 | 5432 | Database of the application | Categories, rules, events and notifications; schema managed by Flyway |
| `keycloak-db` | PostgreSQL 18.7 | – (internal) | Separate database for Keycloak | Keycloak's own data (realm, users, sessions); kept apart from the application data |
| `keycloak` | Keycloak 26.8.2 | 8180 | External authentication server | Login page and access tokens; imports the `sonrisa` realm (`alerts-frontend` client, `USER`/`ADMIN` roles, default users) on first start |
| `mailpit` | Mailpit 1.34.0 | 8025 (web UI), 1025 (SMTP) | Fake mail server | Catches the email notifications; read them at http://localhost:8025 |

Defaults can be overridden by copying `development/.env.example` to `development/.env`.

## Predefined users

The `sonrisa` realm comes with two users:

| Username | Password | Role |
|---|---|---|
| `user` | `user` | `USER` |
| `admin` | `admin` | `ADMIN` |

These are local development accounts only. The Keycloak admin console (http://localhost:8180/admin) has its own `admin` / `admin` account in the `master` realm.

## API documentation

The backend provides OpenAPI documentation (dev profile):

- Swagger UI: http://localhost:8080/swagger-ui.html
- OpenAPI JSON: http://localhost:8080/v3/api-docs

To call the API from Swagger UI, use **Authorize** with a Keycloak access token.

## Suggested test workflow

1. Sign in as `admin` and **create a category** (Categories page).
2. **Create a rule** (My rules page): pick keywords, optionally the category, and a notification target (an email address, or a Slack webhook URL).
3. Go to **Simulate event** and send an event whose title or summary contains one of the rule's keywords.
4. Check the notification: emails in Mailpit (http://localhost:8025), Slack messages in the target channel. The event also appears under Events and in Recently sent.

## Original brief (verbatim)

> "We want users to be able to set up alerts so they get notified when something important happens in the world – like breaking news, market movements, natural disasters, that kind of thing. Should work for both email and Slack. Make it flexible enough that we can add more channels later. We need an admin view too."
